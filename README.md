# 無聲溝通・唇語辨識專題

給失聲者用的無聲溝通系統：對鏡頭無聲說出常用需求，系統辨識嘴型、轉成文字並唸出來。

**網址（電腦、手機都能開）：<https://sakurasnow-0w0.github.io/lipread-ssi/>**

| 頁面 | 用途 |
|---|---|
| 前台輸入 `index.html` | 輸入團隊通關碼即可使用；**引導錄影**（常用句庫、隨機抽句、鏡頭對位檢查、自動提示節奏）；一次上傳多段影片（手機可直接錄），勾選後批次標註「念的內容」→ 自動抓嘴唇節點 → 口型數據存 GitHub、影片存 Google 雲端並自動分資料夾；也能做辨識測試 |
| 後台報告 `report.html` | 準確率、混淆矩陣、嘴型重播比較、資料集覆蓋；可匯出 CSV／Markdown／PDF／原始 JSON |
| 日程 `schedule.html` | 專題總截止倒數、待辦與截止日、時間軸；大家共用同一份 |
| 日誌 `log.html` | 手寫的進度／會議／老師意見，加上系統自動記錄的活動（誰上傳了什麼、改了哪個待辦） |
| 架構 `architecture.html` | 資料流程、可點開的系統心智圖、技術清單（做報告可直接引用） |
| 隱私權 `privacy.html` | 隱私權政策與使用規範（不用登入就能看）；登入後第一次使用要先勾選同意 |

> 要審查程式或找 bug，請先讀 [`docs/HANDOFF.md`](docs/HANDOFF.md)。

## 資料放哪裡

| 內容 | 位置 | 誰看得到 |
|---|---|---|
| 網頁程式 | 這個公開 repo `lipread-ssi` | 所有人（裡面沒有密碼、沒有個資） |
| 口型數據（每段一個 JSON） | 私有 repo `lipread-ssi-data` 的 `data/samples/` | 只有協作者 |
| 影片 | Google 雲端硬碟影片資料夾，依內容自動分子資料夾；引導錄影預設**只錄嘴巴特寫**（不含整張臉） | 只有被分享的人 |

```
唇語影片/

```

## 怎麼開始用

### 一般使用者（同學、志願者）：只要通關碼
1. 打開 <https://sakurasnow-0w0.github.io/lipread-ssi/>
2. 跳出的視窗填「你的名字或代號」和「團隊通關碼」（向專題負責人索取），按「開始使用」
3. 就能上傳影片、做辨識測試、看後台報告。**不需要 GitHub 帳號**

刪除資料需要另外的「管理員密碼」：在同一個視窗展開「我是管理員」填入。管理員密碼只記在當下的分頁，關掉就要重新輸入。

### 開發者：用自己的 GitHub token（選用）
想用自己的 GitHub 身分直接寫入時，在視窗切到「開發者（GitHub token）」。token 建立方式：

| 欄位 | 要選 | 意思 |
|---|---|---|
| Expiration | 設到專題結束 | 時間到自動失效 |
| Resource owner | `Sakurasnow-0w0` | 要開「誰的」repo |
| Repository access | **Only select repositories** → 只勾 **`lipread-ssi-data`** | 只能碰這一個 repo（注意不是 `lipread-ssi`） |
| Permissions → Contents | **Read and write** | 讀寫 repo 裡的檔案 |
| 其他權限 | 全部不動 | Metadata 會自動變 Read-only，這是必要的 |

建立網址：<https://github.com/settings/personal-access-tokens/new>

## 後端服務設定（擁有者設定一次）

網站背後是一支 Google Apps Script（[`apps-script/Code.gs`](apps-script/Code.gs)），負責：
- 把影片存進雲端硬碟，依「念的內容」自動建子資料夾
- **用存在後端的 GitHub token** 把口型數據、日誌、日程寫進私有 repo——token 不在網頁裡，任何人都看不到
- 檢查通關碼／管理員密碼；密碼錯太多次會暫停一分鐘；全站每分鐘上傳次數有上限

### 第一次部署
1. 雲端硬碟建一個影片資料夾，複製網址最後那串資料夾 ID；資料夾分享給隊友（「一般存取權」保持「限制」，影片有人臉）
2. <https://script.google.com> → 新專案，貼上 `Code.gs`（不用改任何一行），存檔
3. 左側齒輪「**專案設定**」→ 最下方「**指令碼屬性**」→ 新增四個：

   | 屬性 | 值 |
   |---|---|
   | `ROOT_FOLDER_ID` | 第 1 步的資料夾 ID |
   | `GITHUB_TOKEN` | 專門給後端用的 Fine-grained token（只勾 `lipread-ssi-data`、Contents 讀寫） |
   | `TEAM_CODE` | 團隊通關碼，給同學用 |
   | `ADMIN_CODE` | 管理員密碼，只有你知道，不要跟通關碼一樣 |

4. 函式選 `setupCheck` → 執行 → 授權（「Google 尚未驗證」→ 進階 → 前往）。執行記錄應顯示四個屬性「已設定」、資料 repo 連線「成功」
5. 「部署 → 新增部署作業」→ 網頁應用程式；執行身分「**我**」、存取權「**所有人**」→ 複製網址，寫進 `assets/config.js` 的 `uploadUrl`

### 修改程式或換密碼
- 更新 `Code.gs`：整份貼上新版（設定都在指令碼屬性，不用改任何一行）→「部署 → **管理部署作業**」→ 鉛筆圖示 → 版本選「**新版本**」→ 部署。**網址不變**，網站不用改
- 換通關碼／管理員密碼／token：直接改「指令碼屬性」即可，**不用重新部署**，立刻生效

上傳後每段樣本會記下雲端檔案編號，後台可直接播放（觀看者要有那個資料夾的權限）。刪除樣本時雲端影片會移到垃圾桶，30 天內可還原。

## 隱私與搜尋引擎

- 每一頁都有 `noindex, nofollow` 標記，Google、Bing 等正規搜尋引擎不會收錄網站
- 沒輸入通關碼時，頁面內容整個隱藏，只顯示登入視窗
- 真正的資料保護在後端：沒有通關碼，讀不到任何口型數據、日程、日誌，也不能上傳
- 注意：網頁程式碼本身是公開的（公開 repo），但裡面沒有任何密碼、token 或資料

## 手機與 iPhone

- 手機開網頁會多一個「錄一段」按鈕，直接開前鏡頭錄影；也可以從相簿一次選多段
- iPhone 的 MOV／HEVC：**在 iPhone 上直接處理沒問題**（Safari 本來就能解 HEVC）。如果要在 Windows 電腦處理 iPhone 傳來的檔案，可能會解不開，這時請在手機上處理，或把 iPhone「設定 → 相機 → 格式」改成「最相容」（改錄 H.264）
- 單段影片上限 30 MB（1–3 秒的影片通常只有幾 MB）

## 常用句庫

前台「引導錄影」的句子在 [`assets/phrases.js`](assets/phrases.js)，參考醫院給失聲病人用的溝通板整理，**是草稿，詞表定案後請直接改這個檔**。隨機抽句會優先抽比較少人錄過的句子，讓每句資料量平均。

不建議讓系統隨機生成任意句子：目前的方法要拿新影片跟「同一句」的範本比，每句都需要多人、多次錄影；任意句子要等之後改用深度學習、而且需要大量資料才做得到。

## 錄影規格

- 一段只念一句，1–3 秒；正面、距離固定、光線均勻；開頭先閉嘴約半秒
- 用電腦資料夾批次匯入時，檔名用 `念的內容_錄製者_編號.mp4`（例如 `我要喝水_A_01.mp4`），會自動標註
- 建議第一批：2 人 × 6 句 × 每句 10 次，先跑通流程再大量錄

## 方法

1. MediaPipe Face Landmarker 逐格取得臉部 478 個節點與表情係數（每格獨立偵測，同一支影片結果可重現）
2. 每格取 20 維嘴部特徵：16 個嘴部表情係數（左右成對平均）＋ 4 個以兩眼距離正規化的嘴型幾何量；另存嘴唇內外輪廓 40 點座標供重播
3. 減去開頭靜止嘴型以降低個人差異，裁掉前後沒動作的影格
4. 用 DTW 計算與每段範本的距離，取最接近的（1-NN）
5. 評估：**留一法**（同一批人，對應「先錄自己的範本」）與**跨錄製者**（只用別人的範本，對應「沒錄範本就直接用」）

限制：只能認出資料庫裡已有的內容；範本比對換人後準確率會明顯下降。

## 之後改用 GitHub Pro（選用）

目前「程式公開、資料私有」已經夠用。若想把程式也設成私有，需要 GitHub Pro 才能開 Pages：學生可申請免費的 [GitHub Student Developer Pack](https://education.github.com/pack)（用學校信箱、上傳學生證，審核約幾天）。通過後到 repo Settings 改成 Private，Pages 會繼續運作。
